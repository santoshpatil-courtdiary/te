Setup & Team

Team Mode (multiple member logins)

In Team Mode every member signs in with their own email and password and shares one live case database. Each change shows who made it. Disable Team Mode to go back to single-user file/Drive mode.
One-time Firebase setup steps
1. Host this HTML on your GitHub Pages (https address).
2. Go to the Firebase console, create a project (free).
3. Add a Web app; copy the firebaseConfig object and paste it above.
4. Build → Authentication → Get started → enable Email/Password.
5. Authentication → Users → Add user for each team member (email + password).
6. Authentication → Settings → Authorized domains → add your GitHub Pages domain.
7. Build → Firestore Database → Create database.
8. Firestore → Rules → allow signed-in users, then Publish:
rules_version = '2'; service cloud.firestore { match /databases/{db}/documents { match /cases/{id} { allow read, write: if request.auth != null; } match /judgments/{id} { allow read, write: if request.auth != null; } match /meta/{id} { allow read, write: if request.auth != null; } } } 9. Build → Storage → Get started (needed so PDFs/photos sync). Then Storage → Rules, paste this and Publish:
rules_version = '2'; service firebase.storage { match /b/{bucket}/o { match /attachments/{allPaths=**} { allow read, write: if request.auth != null; } } } 10. Save the config above, click Enable Team Mode, and sign in.
Case text and hearings sync live through the database; uploaded files sync through Storage. The config is not a secret; access is controlled by the rules and member accounts.

OneDrive Sync (Microsoft account)

If sign-in fails with error AADSTS50194 (not multi-tenant), paste your Directory (tenant) ID from the Azure app Overview page here. Leave blank if your app allows any organizational and personal accounts.
Signs in with your Microsoft (work or personal) account and keeps one file, court-case-diary.json, in the app folder of your OneDrive. Works on Windows, Android and iPad. Use this if Google is blocked on your office laptop.
One-time Microsoft setup steps
1. Host this file on your GitHub Pages so it has an https address, and open it there.
2. Go to the Azure portal → Microsoft Entra ID (Azure AD) → App registrations → New registration.
3. Name it (e.g. Court Diary). Under supported account types choose Accounts in any organizational directory and personal Microsoft accounts.
4. Redirect URI: choose platform Single-page application (SPA) and enter your page URL exactly, e.g. https://yourname.github.io/court-diary.html
5. Register, then copy the Application (client) ID into the box above.
6. API permissions → Add a permission → Microsoft Graph → Delegated → add Files.ReadWrite.AppFolder and User.Read, then Save.
7. Click Save & Connect above and sign in with your Microsoft account.
The client ID is not a secret. The app can only see its own folder in your OneDrive, nothing else.

Google Client ID (single-user Drive)

Paste the Web OAuth Client ID from your Google Cloud project, then Save and click Connect Drive. A Client ID is not a secret, so it is safe to keep here.

One-time setup steps

1. Host this HTML on your GitHub Pages so it has an https web address.
2. Go to Google Cloud Console, create or pick a project.
3. APIs & Services → Library → enable Google Drive API.
4. OAuth consent screen: type External; add your own Google account under Test users.
5. Credentials → Create Credentials → OAuth client ID → type Web application.
6. Under Authorized JavaScript origins add your GitHub Pages origin only, for example https://yourname.github.io (no path, no trailing slash).
7. Copy the generated Client ID into the box above and Save.
The app uses the drive.file scope, so it can only see the single diary file it creates, nothing else in your Drive.
